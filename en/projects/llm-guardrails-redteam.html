LLM guardrails and red team

Guardrails around both agents and a red-team suite that attacks them on every pull request.

Code

26 of 27attacks blocked, each proven to work without the guardrails; one reported as a gap

Decision it supports
Whether an agent can be exposed to external documents and users.
Who uses it
Security and compliance teams, and whoever signs off AI going to production.
What an error costs
A manipulated agent can leak personal data, call the wrong tools or clear a fraud; personal data in logs is a privacy-law risk.
How it creates value
Every known attack is tested on every change, and the build fails if one gets through or if anything legitimate is blocked. Card numbers, CPF and e-mail are masked before they reach the logs.
Risks and limits
Injection detection uses patterns; new attacks can get through, which is why the other layers are tested on their own.

Problem

Agents read documents and call tools, so anyone who can write into a document, a merchant name or a question can try to steer them. A model's own refusals are not a defence, and traces quietly collect the personal data users type.

Solution

Six layers wrapped around the agents without changing their code: input checks, quarantine of instructions found in data, personal-data redaction, a tool policy, output checks and redacted traces. The suite drives the real agents with a model that obeys any instruction it can see, so blocking never depends on a model refusing.

How it works

  • Each attack must succeed without the guardrails and fail with them.
  • Some attacks are worded to evade detection, so the later layers are tested on their own; reworded injections go to a local trained classifier whose threshold the false-positive suite sets.
  • A false-positive suite on real recorded data fails the build if anything legitimate is touched.

Results

Measured results, from the repository
26 of 27attacks blocked across injection, exfiltration, tool misuse, critic bypass and logs
0 of 283real texts flagged; 0 of 22 questions and 0 of 3 investigations changed
79tests; the suite found a bug in the guardrails themselves

Limits

Patterns and a classifier still miss some phrasings: one reworded document instruction gets through and is kept in the suite as a known gap, which is why the later layers are tested separately.
