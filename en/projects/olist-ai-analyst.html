Olist AI analyst

A local-model analyst that turns a business question into a decision memo, with code checking the SQL and every number.

CodeEvaluation results

72%of 25 business questions answered with the same result as hand-written reference SQL

Decision it supports
Any decision that depends on a number from operations: where to invest, what to cut, what to prioritize.
Who uses it
Managers and business teams who today wait for the data team for every question.
What an error costs
A wrong number in a well-written memo leads to a wrong decision that looks right.
How it creates value
A question becomes a memo in about half a minute, with the SQL and rows behind the answer. When the model writes a number that is not in the result, the memo is marked unverified instead of looking trustworthy.
Risks and limits
It gets 68% of the evaluation questions right; it is a first draft for an analyst to review, not a final answer.

Problem

A model writing SQL fails in ways that look right: a query that runs but filters the wrong rows, or a memo that quotes a number the query never produced. An analyst's answer is only worth something if the decision maker can trust it.

Solution

An analyst over the real Olist marketplace data (99,441 orders) that follows the five steps of the Data-Driven Decisions books: name the decision, trust the data, show the work, read the trend and make it last. The model writes the SQL and the memo; code checks the SQL, runs it read-only, reads the trend and requires every number in the memo to exist in the result.

How it works

  • DuckDB's own parser allows one SELECT over three analysis tables, on a read-only connection with file and network access off.
  • Errors go back to the model, up to three tries; a memo with a number not in the result gets one rewrite, then is marked unverified.
  • The trend is read by code from a fitted line over full months, never described by the model.
  • An evaluation with reference SQL runs weekly with Ollama on a free CPU runner and commits its results.

Results

Measured results, from the repository

Limits

A number tied to a named row must be that row's value, but looser wording is not judged; the questions are few and were written by the same person as the pipeline.

Stack

DuckDB, Ollama, Qwen2.5-Coder, GitHub Actions
