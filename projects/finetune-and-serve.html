Fine-tuning e serving

Um modelo de 0,5B ajustado num runner de CPU gratuito para marcar fatos financeiros em frases de 10-K, servido com llama.cpp.

CódigoModelo publicado

0,82de F1 em fatos rotulados por auditores, contra 0,65 de um modelo de 3B com exemplos no prompt

Decisão que apoia
Treinar um modelo próprio ou pagar uma API comercial para uma tarefa de extração.
Quem usa
Quem decide orçamento e arquitetura de IA: tech leads, produto e finanças.
Quanto custa errar
Escolher API com volume alto paga caro por requisição; escolher modelo próprio com volume baixo paga uma máquina parada.
Como gera valor
O modelo pequeno ajustado acerta mais (0,82 contra 0,65) e custa US$ 35 por milhão de requisições em carga total. A conta mostra a partir de qual volume mensal a máquina própria fica mais barata que cada API.
Riscos e limites
A precisão das APIs nessa tarefa não foi medida, só o preço; o custo da VM supõe uso total.

Calcule para o seu cenário: Máquina própria ou API, no seu volume

Custo da VM (US$ 147,17/mês) e capacidade medida (4,2 milhões de requisições por mês por VM) vêm do benchmark do projeto; preços de API são os de tabela. A precisão das APIs nesta tarefa não foi medida.

Problema

Extração estruturada costuma ser feita com um modelo grande e um prompt, e cada requisição paga por um prompt longo, numa API ou num hardware grande o bastante para o modelo. Se um modelo pequeno treinado para essa única tarefa faz melhor e custa menos é uma questão de medição.

Solução

Fine-tuning com LoRA do Qwen2.5-0.5B em frases de notas de 10-K rotuladas por auditores com conceitos XBRL (FiNER-139), exportação para GGUF com quantização de 8 e 4 bits, e serving com llama.cpp. A comparação é com o mesmo modelo e um de 3B usados só com prompt, em qualidade, latência, vazão e custo.

Como funciona

  • Treino, quantização, avaliação e benchmark num único workflow do GitHub Actions numa CPU de 4 núcleos.
  • Perda e logits só nos tokens da resposta, para um vocabulário de 152 mil tokens caber na memória.
  • Todos os modelos servidos pelo mesmo llama-server, com o mesmo schema JSON imposto pela gramática.
  • Custo de uma VM do tamanho do runner contra o preço de tabela das APIs, com o tamanho de prompt medido.

Resultados

Resultados medidos, do repositório
0,82de F1 em 4 bits (398 MB), contra 0,65 do Qwen2.5-3B com seis exemplos (ganho de +0,16, intervalo de 95% por bootstrap pareado de +0,10 a +0,23) e 0,19 antes do ajuste
3,7×as requisições por segundo do modelo de 3B na mesma CPU (1,60 contra 0,43)
US$ 35por milhão de requisições auto-hospedado em carga total; o Claude Haiku 5.5 a preço de tabela custaria de US$ 45 a US$ 91

Limites

Um único treino, interrompido pelo limite de tempo em 79% de uma época; a precisão das APIs nessa tarefa não foi medida, só o preço.
