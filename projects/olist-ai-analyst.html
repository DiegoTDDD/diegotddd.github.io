Analista de dados com IA (Olist)

Um analista com modelo local que transforma uma pergunta de negócio num memo de decisão, com código conferindo o SQL e cada número.

CódigoResultados da avaliação

72%de 25 perguntas de negócio respondidas com o mesmo resultado do SQL de referência escrito à mão

Decisão que apoia
Qualquer decisão que dependa de um número da operação: onde investir, o que cortar, o que priorizar.
Quem usa
Gestores e áreas de negócio que hoje esperam o time de dados para cada pergunta.
Quanto custa errar
Um número errado num memo bem escrito leva a uma decisão errada com cara de certa.
Como gera valor
A pergunta vira memo em cerca de meio minuto, com o SQL e as linhas que sustentam a resposta. Quando o modelo escreve um número que não está no resultado, o memo sai marcado como não verificado em vez de parecer confiável.
Riscos e limites
Acerta 68% das perguntas da avaliação; serve como primeiro rascunho para um analista revisar, não como resposta final.

Problema

Um modelo escrevendo SQL erra de jeitos que parecem certos: uma consulta que roda mas filtra as linhas erradas, ou um memo que cita um número que a consulta nunca produziu. A resposta de um analista só vale se quem decide puder confiar nela.

Solução

Um analista sobre os dados reais do marketplace Olist (99.441 pedidos) que segue os cinco passos dos livros Data-Driven Decisions: nomear a decisão, confiar no dado, mostrar o trabalho, ler a tendência e fazer durar. O modelo escreve o SQL e o memo; o código confere o SQL, roda em modo só leitura, lê a tendência e exige que cada número do memo exista no resultado.

Como funciona

  • O próprio parser do DuckDB só aceita um SELECT sobre três tabelas de análise, numa conexão só leitura, sem acesso a arquivos ou rede.
  • Erros voltam para o modelo, até três tentativas; um memo com número fora do resultado ganha uma reescrita e depois é marcado como não verificado.
  • A tendência é lida pelo código, numa reta ajustada sobre meses completos, nunca descrita pelo modelo.
  • Uma avaliação com SQL de referência roda toda semana com Ollama num runner de CPU gratuito e publica os resultados.

Resultados

Limites

Um número ligado a uma linha nomeada precisa ser o valor dessa linha, mas frases mais soltas não são julgadas; as perguntas são poucas e foram escritas pela mesma pessoa que fez o pipeline.

Stack

DuckDB, Ollama, Qwen2.5-Coder, GitHub Actions
