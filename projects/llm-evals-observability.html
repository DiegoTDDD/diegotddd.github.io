Avaliação e observabilidade de LLMs

Uma barreira contra regressões a cada pull request e avaliações semanais ao vivo rastreadas no Langfuse.

CódigoPainel

162chamadas reais de ferramenta reproduzidas a cada pull request

Decisão que apoia
Liberar ou não uma mudança num sistema com IA.
Quem usa
Times que mantêm agentes e LLMs em produção.
Quanto custa errar
Uma mudança que piora o agente chega ao usuário sem ninguém perceber.
Como gera valor
Cada pull request é testado contra 162 chamadas reais gravadas; uma regressão real já foi barrada antes de ir para o ar. O painel mostra a qualidade ao longo do tempo.
Riscos e limites
Resultados ao vivo variam entre execuções; a barreira usa tolerâncias medidas, não valores exatos.

Problema

Agentes com modelos locais pequenos falham de jeitos que testes unitários não enxergam: o modelo manda argumentos que as ferramentas rejeitam, uma resposta nunca termina, uma correção num ponto quebra outro.

Solução

Datasets versionados gravados de execuções reais, uma barreira offline que os reproduz a cada pull request, execuções semanais ao vivo dos dois agentes rastreadas com OpenTelemetry num Langfuse auto-hospedado, e um painel público.

Como funciona

  • Os datasets são imutáveis e versionados com manifesto sha256.
  • As linhas de base têm tolerâncias medidas a partir da variação entre execuções.
  • O Langfuse roda dentro do CI com Docker Compose, então o rastreamento é testado de ponta a ponta.

Limites

Os resultados ao vivo variam entre execuções do mesmo código; a barreira usa tolerâncias em vez de valores exatos.
